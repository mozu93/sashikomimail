# 差し込みメール送信 管理者マニュアル

対象バージョン：1.1.4

## 1. システム構成

| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11 64ビット |
| UI | PyQt6 |
| データ保存 | SQLite |
| メール送信 | Microsoft Graph API |
| 認証 | OAuth2委任認証（MSAL） |
| トークン保護 | OS暗号化付きMSALキャッシュ |
| 業務データ保護 | Windows DPAPI |
| 配布 | PyInstaller / Inno Setup |

## 2. Microsoft Entra ID設定

1. Microsoft Entra管理センターでアプリ登録を作成
2. 「認証」で「モバイルとデスクトップ アプリ」を構成
3. パブリッククライアントフローを許可
4. Microsoft Graphの委任されたアクセス許可`Mail.Send`を追加
5. 代理差出人を使用する場合は`Mail.Send.Shared`を追加
6. テナントIDとクライアントIDを利用者へ安全に案内

代理差出人には、Exchange Online側で認証ユーザーへ「メールボックス所有者として
送信」または必要な代理送信権限を付与します。

クライアントシークレットは使用しません。アプリへ秘密情報を入力・配布しないで
ください。

## 3. DNS・到達性

送信ドメインでは、SPF・DKIM・DMARCを設定してください。大量の広告・
ニュースレター配信にはMicrosoft 365ではなく専用配信サービスを使用します。

アプリは送信間隔を最低2秒に制限しますが、Microsoft 365のテナント・メールボックス
送信制限は別途適用されます。

### 「受理」と到達の違い

アプリが記録する「受理」は、Graph APIの`sendMail`が`202 Accepted`を返した
状態です。到達を保証するものではありません。宛先ごとの配信結果は、Exchange
管理センターの「メールフロー → メッセージ追跡」で確認します。`Delivered`、
`Failed`、`FilteredAsSpam`と、受信側サーバーの応答内容を確認できます。

### 配信不能通知（NDR）の返送先

代理差出人を使用した送信では、エンベロープ送信者が代理差出人になるため、
NDRと返信は認証アカウントではなく代理差出人のメールボックスへ届きます。
共有メールボックスを代理差出人にしている場合、担当者が受信トレイを
参照できるよう権限を付与してください。

### 通知が返らない不達

次のケースでは、送信側にエラーが返らないまま不達になります。送信履歴では
検知できないため、利用者への事前案内が必要です。

- 携帯キャリア（docomo、au、SoftBank）のなりすまし規制・パソコンメール拒否
- 受信側の迷惑メールフォルダへの振り分け
- 実在する誤記ドメイン（例：`dokomo.ne.jp`）への誤送信。第三者がMXを運用して
  いるため受理され、添付ファイルごと社外へ渡る情報漏えいになる

アプリはv1.1.4から、誤記が疑われるドメインと携帯キャリア宛の件数を
送信前に警告します。検出パターンは`app/core.py`の`TYPO_DOMAINS`と
`CARRIER_DOMAINS`で管理し、新たな誤記が判明した場合は追加してください。

## 4. 開発環境

```powershell
python -m venv venv
venv\Scripts\activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python main.py
```

## 5. EXEビルド

```powershell
.\build.ps1
```

テスト合格後、次へ出力されます。

```text
dist\SashikomiMail\SashikomiMail.exe
```

配布時は`dist\SashikomiMail`フォルダ一式を使用します。EXE単体ではなく、
同じフォルダの依存ファイルも含めてください。

## 6. インストーラー

Inno Setup 6を導入し、`installer\setup.iss`をコンパイルします。

```text
installer_output\SashikomiMail-Setup-1.1.4.exe
```

インストーラーは利用者権限でインストールし、必要に応じてデスクトップ
ショートカットを作成します。

## 8. データ保存

```text
%APPDATA%\SashikomiMail\sashikomi_mail.db
%APPDATA%\SashikomiMail\token_cache.bin
%APPDATA%\SashikomiMail\sashikomi_mail.log
```

名簿、送信対象、宛先、件名、エラー内容、テスト送信先はDPAPIで暗号化されます。
原則として、暗号化したWindowsユーザーとPCでのみ復号できます。

複数PCで同じSQLiteファイルを共有しないでください。

## 9. バックアップと復元

利用者は設定画面からデータベースをバックアップできます。復元時はアプリを終了し、
同じWindowsユーザー・PCで、元ファイルを退避してからバックアップを
`sashikomi_mail.db`へ戻します。

復元作業前に現行データを別名で保存してください。

## 10. 履歴保持

初期設定は365日です。設定画面で30～3650日に変更できます。起動時に保存期間を
超えた履歴を削除します。個別履歴は履歴画面から削除できます。

## 11. ログと障害対応

未処理例外は`sashikomi_mail.log`へ記録されます。送信失敗は送信履歴の明細へ
記録されます。

確認項目：

1. 発生日時と利用者
2. アプリのバージョン
3. 認証アカウントと代理差出人
4. Graph APIのHTTPステータスとエラー本文
5. 添付ファイルの存在・容量
6. Microsoft 365のメッセージ追跡
7. Entra IDサインインログ

個人情報を含むログやデータベースを、承認なく社外サービスへアップロードしないで
ください。

## 12. アンインストール

インストーラー版はWindowsの「インストールされているアプリ」から削除します。
アンインストール後も業務データは`%APPDATA%\SashikomiMail`へ残る場合があります。
保存義務と社内規程を確認し、不要な場合のみ手動削除します。
